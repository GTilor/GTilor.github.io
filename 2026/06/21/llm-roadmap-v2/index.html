LLM Alignment & Reasoning Roadmap

顶部说明

  • 主线：发挥数学优势，跳过基础科普，直击 LLM 底层对齐算法与推理强化的数学本质。
  • 总时长：26 周（6 个月全职，每天 5-8 小时）。
  • 学习者背景：应用数学研0，有 PyTorch 训练经验（CG-FVT-FULD 优化器），已手写 Transformer 和看过 nanoGPT。RL 基础为零。
  • 核心目标：成为 LLM 专家——懂全局、懂 why、跟得上前沿、有出口产物、为求职和科研打基础。
  • 导师方向：应用数学（优化 + 控制 + 多智能体编排），希望与 LLM 结合。M3/M4 的产出应尽量对齐导师课题。
  • 新增原则：
    • 每 4 周嵌入 1 个轻周（只读论文 + 整理 notes，不写代码）
    • 每个项目区分 minimum viable 和 stretch 目标，延期砍 stretch
    • 每个里程碑结束时写一段「这个项目怎么写进简历」的产出总结
    • 并行线：从 W1 起每天 30-60 分钟刷 LeetCode（不占用 LLM 学习时间，详见底部「并行准备线」）
    • 硕士定位原则：字节前沿技术岗（大模型/AI Coding/AIGC）只招博士，硕士瞄准此岗=零机会。本路线图面向硕士求职，主攻阿里/腾讯/美团/京东的硕士友好 LLM 算法岗。把目标岗位 JD 打印贴墙，每周对照加分项（顶会 paper / 开源项目 / Agent 落地 / 百亿级预训练或 RLHF 实战 / 实习）逐条映射到 M2-M4 产出。

🎯 核心学习方法论（参考 lvy010/X-Plore）

lvy010（05 后本科生，2 年从 C++ 系统编程转向 AI Infra，千篇笔记 + 27 个项目）的方法论值得借鉴。他是"系统工程师视角的 AI 学习"——不追新模型，搞清楚 AI 系统的调度/内存/工具/运行时如何分层。

四条铁律（与 CS Systems Roadmap 共享）

  1. nano project 法则：绝不一上来就看庞大的工业源码（如 vLLM, Megatron）。一切从 1000 行以内的微缩版项目（如 nanoGPT, nano-vllm）开始，看懂后直接白板复写。
  2. 源码精读法则：每读一个项目，按"逐文件拆解到类/函数/数据结构级别"写笔记。参考 lvy 对 nanoGPT 的 10 篇拆解（数据预处理 → 模型架构 → 训练编排 → 检查点 → 生成 → 性能优化）。
  3. 输出法则：每天遇到重大 insight，必须产出一篇 Markdown 笔记。画架构图（Mermaid/ASCII），放核心代码，记录你的思考过程。lvy 原话：“Document everything - recording the learning process itself is a contribution.“
  4. 三阶段演进法则：从"调 API → 读源码 → 自己实现"递进。每个方向都要走完这三步，不能停留在调 API。

nano project 学习路径（lvy010 推荐，大模型 Infra 专用）

核心理念：“先建立宏观脉络 → 学核心小项目 → 深入大项目“，避免被生产级框架的复杂代码干扰。

与本路线图的映射：

  • M1 P1（nanochat）→ nanochat 节点 ✅
  • M1 P3（modded-nanogpt）→ Training 层入口 ✅
  • M2 P5（minimind + trl）→ RL 层入口 ✅
  • M3（verl + ReST-MCTS）→ RL 层深入 ✅
  • M4 P9（vLLM/SGLang）→ Inference 层深入 ✅
  • 缺口：nano-vllm 源码精读（建议在 M4 P9 之前补上，作为 vLLM 源码精读的预热）

源码精读模板（参考 lvy 对 nanoGPT 的 10 篇拆解）

每读一个开源项目，按以下顺序拆解并写笔记：

  1. 快速上手：跑通官方 demo，记录环境/依赖/坑点
  2. 数据预处理：分词、数据加载、batch 构造
  3. 模型架构：逐层拆解（如 nanoGPT 的 LayerNorm → CausalSelfAttention → MLP → Block）
  4. 配置系统：configurator.py 这类"小但关键"的文件（lvy 专门拆了 exec() & globals()）
  5. 训练编排：get_batch / optimizer / lr scheduler / 分布式（DDP）
  6. 检查点：保存/加载/预训练模型加载
  7. 生成：自回归采样、KV cache
  8. 性能优化：torch.compile / Flash Attention / 混合精度 / MFU 估算
  9. 全栈实现：如何把训练好的模型变成可对话的产品
  10. 对比思考：与同类项目的差异（如 nanoGPT vs modded-nanogpt）

2. 简历意识（每个里程碑结束时）

每个里程碑结束时，花 30 分钟写一段「简历条目」：

  • 用 STAR 格式（Situation-Task-Action-Result）
  • 量化成果（如「复现 GRPO，在 GSM8K 上 pass@1 从 X% 提升到 Y%」）
  • 到 W26 时应该有 4-5 条可用的项目描述
